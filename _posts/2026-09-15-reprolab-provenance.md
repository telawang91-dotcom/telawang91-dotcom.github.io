科研 Agent 和普通聊天机器人最大的区别之一，是“答案看起来合理”远远不够。一个数字如果进入论文、报告或决策，就必须回答：它来自哪份数据、经过哪段代码、在哪个环境里计算、能不能重新得到。

ReproLab 的核心设计因此不是聊天界面，而是一条可追溯链：

```text
Dataset → Run → Artifact → Claim
```

## Dataset：输入必须有身份

同名文件不等于同一份数据。真正可复现的系统需要识别“内容本身是否变化”。

因此数据输入更适合绑定内容哈希、版本和项目作用域。这样即使用户把 `data.csv` 替换成另一份同名文件，系统也能知道输入发生了变化。

## Run：一次执行不是临时过程

一次分析执行需要留下：

- 使用了哪些输入；
- 执行了什么代码；
- 使用什么依赖环境；
- 随机种子或关键参数；
- 成功还是失败；
- 产生了哪些输出。

只有 Run 被持久化，后续“重跑”和“比较”才有依据。

## Artifact：数字、表格、图都应该是一等公民

传统聊天式分析常把结果直接写进回答里，过一会儿就不知道这个数字怎么来的。

ReproLab 把数字、表格、图片、文件都看成 Artifact，并绑定它们的来源 Run。于是一个报告中的数字可以反向找到：

```text
Claim
  ↓ supported by
Artifact
  ↓ produced by
Run
  ↓ reads
Dataset
```

这比仅仅保存一段模型回答可靠得多。

## Claim：结论必须引用证据

最终文本里的结论，不应该凭模型记忆直接生成。更稳妥的做法是让 Claim 显式引用文献证据或计算 Artifact。

于是系统可以检查：

- 数字是否真的存在；
- 引用是否真的支持这句话；
- 图表与底层数据是否一致；
- 数据更新后结论是否发生漂移。

## 为什么要记录环境

即使数据和代码都没变，环境变化也可能导致结果变化。

因此一个可信执行至少需要考虑：

```text
env_hash
input_hash
code_hash
```

代码、输入和环境共同组成一次计算的信任锚点。

## 漂移不是简单比较 PNG

图表重新生成后，PNG 字节可能因为渲染细节发生变化，但图表达的数据并没有变化。因此复现比较应该尽量靠近语义层：

- 数值按容差比较；
- 表格比较结构和单元格；
- 图形比较绘图数据与关键属性；
- 文件比较内容哈希。

## 为什么这件事对 Agent 特别重要

Agent 会动态规划和动态生成代码，所以它比固定脚本更容易产生“这次能跑、下次不知道为什么不一样”的问题。

因此越是自动化的系统，越需要更强的 Provenance。

## 核心结论

可信不是“换一个更强模型”得到的属性，而是系统通过**数据血缘、可复现执行和验证规则**强制建立出来的。

这也是 ReproLab 最想表达的一件事：AI 可以负责提出和执行分析，但证据链必须由工程系统掌握。
